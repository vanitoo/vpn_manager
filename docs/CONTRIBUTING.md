# Contributing

Спасибо за интерес к Warp Private Network.

## Перед изменениями

1. Проверьте существующие Issues и Pull Requests.
2. Для крупной функции сначала опишите пользовательский сценарий и ожидаемый результат.
3. Не добавляйте в Git `.env`, токены, рабочие базы, резервные копии и логи с персональными данными.
4. Основная рабочая ветка проекта — `main`.

## Локальная разработка

```bash
git clone https://github.com/vanitoo/vpn_manager.git
cd vpn_manager
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.main
```

Контейнерный запуск:

```bash
docker compose up -d --build
```

## Правила кода

- сохраняйте асинхронную модель aiogram/aiohttp;
- не помещайте SQL и бизнес-логику в клавиатуры и форматирование сообщений;
- операции хранения держите в `db.py`, профильных storage-модулях или специализированных слоях;
- интеграции должны безопасно переживать отключённую конфигурацию;
- код Remnawave должен учитывать различия API 2.x и 3.x;
- не предполагайте, что Remnawave ID всегда UUID;
- не логируйте секреты, полные платёжные данные и subscription URL без необходимости;
- пользовательские ошибки должны быть понятными и не раскрывать внутренние детали системы.

## Изменение схемы данных

SQLite используется в production, поэтому изменения схемы должны быть обратно совместимыми с существующей базой.

Если добавляется поле или таблица:

- задайте безопасное значение по умолчанию;
- не уничтожайте существующие данные;
- обновите `DB_SCHEMA_VERSION`, если изменение относится к основной схеме;
- опишите ручной или автоматический путь обновления;
- проверьте запуск поверх существующей базы.

## Документация

Проектная документация находится в `docs/`. В корне остаётся `README.md`.

При изменении поведения обновляйте подходящий файл:

- `docs/ARCHITECTURE.md` — архитектура и границы модулей;
- `docs/CHANGELOG.md` — пользовательские и технические изменения;
- `docs/ROADMAP.md` — дальнейшие планы;
- `docs/SUPPORT.md` — HelpDesk;
- `docs/SECURITY.md` — безопасность;
- `docs/KODA.md` — краткий контекст проекта для разработки.

Новая заметная функция должна получить запись в `docs/CHANGELOG.md` в секции `Unreleased`.

## Коммиты

Предпочтительны короткие сообщения, описывающие результат:

```text
Add payment history to My VPN
Fix Remnawave v3 user lookup
Refresh project documentation
```

Не смешивайте несвязанный рефакторинг и функциональные изменения без необходимости.

## Pull Request

В описании укажите:

- что изменено;
- зачем;
- как проверить;
- какие переменные окружения добавлены;
- затрагивается ли схема БД;
- есть ли влияние на Remnawave 2.x/3.x;
- известные ограничения.

## Безопасность

Уязвимости не публикуются в обычном Issue. Используйте порядок из [SECURITY.md](SECURITY.md).
