# Архитектура Warp Private Network

## Назначение

Warp Private Network — Telegram-платформа для продажи и управления VPN-доступом через Remnawave. Бот объединяет пользовательские сценарии, платежи, локальное состояние подписок, поддержку через Telegram Topics, рассылки и административные инструменты.

## Общая схема

```text
Telegram user / admin
        │
        ▼

          (2.x / 3.x auto)

        ▼                ▼
      users          nodes/squads
```

## Точка входа и запуск

- `app/main.py` — минимальная точка входа.
- `app/boot.py` — инициализация настроек, БД, логирования, routers, фоновых задач и polling.
- `app/config.py` — единая конфигурация из `.env`.
- `app/runtime.py` — общие runtime-зависимости и выдача VPN-доступа.
- `app/version.py` — версия приложения, дата сборки и версия схемы БД.

## Пользовательский слой

- `app/user_vpn_handlers.py` — экран `Мой VPN`, персональная ссылка, имя, баланс, срок действия, история платежей и переход к подключению.
- `app/user_account.py` — данные пользовательского аккаунта и выборка истории платежей.
- `app/keyboards.py` — inline-клавиатуры.
- `app/faq.py` и `app/faq_handlers.py` — управляемый FAQ.
- `app/covers.py` — пользовательские изображения/обложки.

Баланс `balance_rub` сейчас является полем аккаунта и отображается пользователю. Полноценная логика пополнения и списания кошелька пока не реализована.

## Платежи

Основные таблицы платежей находятся в `app/db.py`. Пользовательские сценарии внешних оплат — в `app/external_payment_handlers.py`.

Провайдеры изолированы в `app/payments/`:

- Telegram Stars;
- YooKassa;
- Cryptomus;
- Lava;
- Platega.

Отключённый или неполностью настроенный провайдер не должен ломать запуск приложения. Доступ выдаётся только после подтверждения успешной оплаты.

## Remnawave

`app/remnawave.py` — version-aware клиент Remnawave. Он автоматически определяет основную версию API и поддерживает 2.x и 3.x.

Клиент отвечает за:

- поиск и создание пользователя;
- продление срока;
- блокировку и активацию;
- работу с squads;
- получение subscription URL;
- синхронизацию локальной записи с Remnawave ID;
- диагностические запросы.

В Remnawave 2.x идентификатором пользователя обычно служит UUID. В 3.x используется числовой `id`; код не должен предполагать один формат идентификатора.

## Административный слой

Основные модули:

- `app/admin_users_handlers.py` — пользователи, статусы, служебный доступ;
- `app/admin_plan_handlers.py` — тарифы;
- `app/admin_remna_handlers.py` — Remnawave;
- `app/admin_squads_handlers.py` — squads;
- `app/admin_mailing_handlers.py` — рассылки;
- `app/admin_ops.py` — системные и операционные действия;
- `app/backup_handlers.py` — резервные копии.

## Поддержка

Поддержка выделена в `app/support/` и использует Telegram forum topics как операторский интерфейс.

Поток:

```text
Помощь
  → инструкция по подключению / FAQ
  → диагностика
  → категория обращения
  → тикет в SQLite
  → отдельная Telegram topic
  → обмен сообщениями
  → закрытие
```

SQLite остаётся источником истины для тикетов и сообщений; Telegram-группа — интерфейс операторов.

Подробнее: [SUPPORT.md](SUPPORT.md).

## Хранение данных

Основные сущности:

```text
users
plans
subscriptions
payments
receipt_contacts
mailing_rules
faq_items
support_tickets
support_messages
app_settings
app_meta
```

База рассчитана на один основной экземпляр приложения. Для локальных изменений схемы используются проверяемые добавления колонок и `DB_SCHEMA_VERSION`, но полноценная система последовательных миграций остаётся задачей до 1.0.

## Дополнительные продукты

`app/products/` — изолированный слой для дополнительных продуктов. SOCKS5 находится отдельно от VPN и выключен по умолчанию через `SOCKS5_ENABLED=false`.

## Источники истины

- VPN-пользователь и параметры доступа — Remnawave;
- локальные подписки, платежи, аккаунт, FAQ и поддержка — SQLite;
- подтверждение платежа — соответствующий платёжный провайдер;
- конфигурация — environment variables;
- Telegram — транспорт и UI, но не основное хранилище бизнес-данных.

## Ограничения текущей версии

- основной режим — polling;
- SQLite;
- один экземпляр приложения;
- нет публичного REST API;
- нет распределённых блокировок;
- баланс пока информационный, без кошелька пополнения/списания;
- доступность поддержки зависит от Telegram Bot API.
