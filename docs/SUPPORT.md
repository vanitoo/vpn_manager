# Поддержка через Telegram Topics

## Обзор

HelpDesk встроен в основной Telegram-бот, но реализован отдельным модулем `app/support/`. Пользователь общается с ботом в личном чате, оператор отвечает через Telegram supergroup с включёнными Topics.

SQLite является источником истины для тикетов и сообщений. Telegram Topics используются как интерфейс операторов.

## Пользовательский сценарий

```text
❓ Помощь
  ├─ 📲 Как подключить VPN
  ├─ 📖 FAQ
  ├─ 🩺 Диагностика
  └─ 💬 Написать специалисту
```

Перед созданием обращения пользователь выбирает категорию проблемы. Диагностика выполняется до эскалации к оператору, чтобы простые случаи решались без тикета.

Типовые категории:

- VPN не подключается;
- проблема с оплатой;
- потеряна ссылка;
- низкая скорость;
- другое.

## Настройка Telegram-группы

1. Создайте отдельную Telegram-группу.
2. Убедитесь, что это supergroup.
3. Включите `Темы`.
4. Добавьте бота администратором.
5. Разрешите отправку сообщений и управление темами.
6. Отправьте `/chatid` в группе.
7. Запишите полученный ID в `.env`.

```env
SUPPORT_ENABLED=true
SUPPORT_GROUP_ID=-1001234567890
```

После изменения `.env` перезапустите бота.

## Создание тикета

При первом сообщении обращения:

1. создаётся запись `support_tickets`;
2. создаётся Telegram topic;
3. topic связывается с тикетом через `message_thread_id`;
4. оператор получает карточку пользователя и диагностику;
5. сообщение пользователя копируется в тему;
6. событие сохраняется в `support_messages`.

## Карточка оператора

В карточке используются только доступные данные. Она может включать:

- номер и категорию тикета;
- Telegram ID;
- имя и username;
- локальный статус подписки;
- тариф;
- дату окончания;
- наличие subscription URL;
- Remnawave ID;
- squad;
- платежную историю;
- результат автоматической диагностики.

Секреты и полная персональная subscription URL не должны без необходимости дублироваться в операторские сообщения и логи.

## Ответ оператора

Оператор пишет обычное сообщение внутри темы. Бот доставляет его пользователю в личный чат и сохраняет связанное событие.

Поддерживаются основные типы Telegram-контента:

- текст;
- фото;
- видео;
- документы;
- аудио;
- голосовые;
- анимации;
- стикеры.

## Команды оператора

```text
/take   взять обращение в работу
/wait   ожидать ответа пользователя
/close  закрыть тикет и тему
```

Основные статусы:

```text
new
in_progress
waiting_user
closed
```

Обычный ответ оператора может перевести новый тикет в работу. Пользователь также может закрыть собственное обращение через интерфейс бота.

## Хранение данных

### `support_tickets`

Хранит пользователя, категорию, статус, Telegram topic, назначенного оператора и временные метки.

### `support_messages`

Хранит направление сообщения, Telegram message IDs, тип вложения и текстовое представление, необходимое для истории.

Удаление Telegram topic не должно использоваться как замена штатному закрытию тикета.

## Диагностика

Автоматические проверки могут включать:

- наличие пользователя в локальной базе;
- активную подписку;
- срок действия;
- наличие subscription URL;
- Remnawave ID;
- тариф;
- недавние платежи;
- доступность Remnawave API.

Поддержка Remnawave должна учитывать обе major-версии API: 2.x и 3.x.

## Работа операторов

- отвечайте только внутри темы нужного тикета;
- используйте `/take`, если обращение взято в работу;
- используйте `/wait`, когда требуется ответ клиента;
- завершайте обращение через `/close`;
- не отправляйте пользователю внутренние токены, raw API responses и traceback;
- не копируйте subscription URL в посторонние чаты;
- не удаляйте тему вместо закрытия тикета.

## Диагностика проблем HelpDesk

Если topic не создаётся, проверьте:

- `SUPPORT_ENABLED=true`;
- правильность `SUPPORT_GROUP_ID`;
- что группа является supergroup и Topics включены;
- права администратора у бота;
- логи приложения.

Если ответ не доставляется пользователю:

- пользователь мог заблокировать бота;
- topic может быть не связан с тикетом;
- сообщение может содержать неподдерживаемый тип;
- Telegram Bot API может быть временно недоступен.
